# 網頁本機報表與手機操作

網頁版自 v0.4.15 起自動保留最近一份完整查詢報表，包含原帳號身分、期間、門店、摘要、交易趨勢及所有期間的商品明細。此功能與最多 20 份的歷史摘要分開；完整報表只有一份，不會跨裝置同步。

查詢成功且所有期間明細載入完成後，才提交本機保存。未完成或失敗的查詢不覆蓋上一份已提交報表。服務端工作階段仍於閒置兩小時後清除，完整本機報表不依賴該工作階段。

## 儲存與恢復

- 小型報表使用 `localStorage` 的 `rta-sales-report-v1`，內容為版本、帳號 ID／顯示名稱、儲存時間、輕量摘要與字典壓縮的明細。
- 超過 4,000 筆明細、單一期間字典超過 300,000 字元、JSON 超過 1,000,000 字元，或 localStorage 寫入失敗時，使用 IndexedDB 資料庫 `rta-sales-report-cache-v1` 的 `report/latest`。localStorage 只保留小型指標；IndexedDB 交易提交後才發布指標及保存狀態。
- 寫入／清除依序執行；「儲存完成」只在成功提交後顯示。空間不足或儲存被封鎖時，保留目前已載入資料並顯示警告。
- 重新開頁優先讀取完整本機報表與原帳號。讀取／搜尋／比較／商品詳情／PDF 資料組裝不需要重新登入 RTA。更新資料會先開啟原查詢條件並重新載入門店，仍需按開始分析。
- 本機 PDF memo 及字型文字使用原始完整明細，支援各門店與商品篩選。Excel 活頁簿組裝仍使用網站 API，不需要 RTA 報表工作階段；不宣稱整個網站離線可用。
- 清除本機報表需在畫面確認，會移除 localStorage 和 IndexedDB 的完整報表，保留帳號、常用條件與歷史摘要。
- 瀏覽器清除網站資料、無痕模式、裝置儲存空間不足或儲存遭驅逐仍可能導致資料無法恢復。舊版只存摘要的報表若服務端已過期，須重新查詢一次才能保存完整明細。

## 操作與錯誤恢復

首次 API 同步建立 HttpOnly 工作階段 cookie 後才開啟 SSE，避免首次並行請求各建一個工作階段。重新同步會重綁事件連線。

無法找到結果時使用 `analysis_expired`，亦相容舊版 origin 的英文錯誤。明細佇列遇到此錯誤即停止，不再連續向五個期間發送必定失敗的請求。畫面保留已載入資料，顯示一個中文提示及重新查詢入口；一般暫時失敗仍可只重試明細。

760px 以下：查詢按鈕置於表單末端；底部五個導覽項目保留空間，不蓋住內容；六個報表分頁採三欄兩列。表格預設卡片，以每頁 50 筆控制 DOM 大小，商品先顯示淨銷售額、數量與門店，其餘欄位可展開。可切回完整表格並左右滑動，匯出範圍及欄位不變。短視窗取消重疊固定工具列，側邊導覽可捲動。
